# AnalyzaX — Security Architecture & Guardrails

This document outlines the threat modeling, defense-in-depth principles, SQL sandboxing, input sanitization, and secrets management protocols for **AnalyzaX**.

## 2. SQL Analytics Sandboxing & AST Validation

Treat **all** SQL queries—especially those generated by the AI—as untrusted, potentially hostile input.

### Allowed SQL Constructs
- `SELECT`
- `FROM`
- `WHERE`
- `GROUP BY`
- `ORDER BY`
- `HAVING`
- `JOIN` (INNER, LEFT, RIGHT, FULL, CROSS)
- `LIMIT` / `OFFSET`
- `WITH` (Common Table Expressions / CTEs)
- Standard deterministic analytical functions (`SUM`, `AVG`, `COUNT`, `MIN`, `MAX`, `MEDIAN`, `STDDEV`, `RANK`, `DENSE_RANK`, `ROW_NUMBER`)

### Strictly Blocked SQL Statements & Keywords
The AST parser (using `sqlglot`) immediately raises a validation error if any of the following tokens appear:
- Data Modification: `INSERT`, `UPDATE`, `DELETE`, `MERGE`
- Schema Mutation: `CREATE`, `ALTER`, `DROP`, `TRUNCATE`, `RENAME`
- System & Extension Access: `INSTALL`, `LOAD`, `ATTACH`, `DETACH`, `PRAGMA`
- Filesystem & Execution Functions: `COPY`, `read_parquet` (when invoked directly by user queries), `read_csv`, `read_json`, `system`

### DuckDB Engine Constraints
1. **Connection-level Configuration:**
   ```sql
   SET enable_external_access = false;
   SET lock_configuration = true;
   ```
2. **Execution Timeout:** Strict statement timeout set to 15 seconds per query.
3. **Hard Row Limit:** Queries without a `LIMIT` clause are automatically rewritten to append `LIMIT 1000`. Maximum allowable manual limit is capped at 10,000 rows for API transmission.
4. **Memory Containment:** `max_memory` restricted to 4 GB.

## 3. File Ingestion & Storage Defense

1. **Magic Byte Verification:**
   - File extensions are ignored for trust decisions.
   - Files claiming to be CSV/Parquet/Excel must validate against their true MIME type and magic header bytes (using `python-magic`).
   - Binaries, executable scripts (`.sh`, `.bat`, `.exe`, `.py`), or HTML/SVG files are immediately rejected.
2. **Path Traversal Defense:**
   - Client-provided filenames are completely sanitized (using `werkzeug.utils.secure_filename`).
   - Files are stored using internal UUIDs (`ds_8f72ab91/raw_file.csv`) to prevent directory traversal (`../../etc/passwd`).
3. **Decompression Bomb Defense:**
   - Excel (`.xlsx`) files are zip archives and vulnerable to zip-bombs.
   - Upload streams enforce a strict uncompressed size ceiling (e.g., max 500 MB) during parsing.
4. **Oversized Payload Protection:**
   - HTTP requests enforce `MAX_UPLOAD_SIZE_MB` at both reverse proxy (Nginx) and FastAPI middleware levels.

## 4. AI & Prompt Injection Defenses

1. **Structured Data Delimitation:**
   - System prompts use strict XML-style demarcations (`<dataset_schema>`, `<query_context>`, `<user_question>`).
   - User inputs are never interpolated directly into instruction headers.
2. **Deterministic Tool Gating:**
   - The AI cannot execute arbitrary Python code or shell commands.
   - The AI only has access to typed, Pydantic-validated analytical tools.
   - If the AI proposes an invalid tool call or unverified SQL, the tool execution fails gracefully and prompts the model to self-correct.
3. **Zero JavaScript Generation:**
   - The LLM is prohibited from outputting executable JavaScript or HTML for visualization. All chart outputs are purely declarative JSON option objects.

---

## 5. Secrets Management & Environment Isolation

1. **API Key Isolation:**
   - `OPENROUTER_API_KEY`, database credentials, and session secrets exist exclusively in `.env` and host environment variables.
   - **Never** forward API keys to the frontend or expose them via client-side bundles (`NEXT_PUBLIC_` is strictly restricted to non-sensitive public URLs).
2. **Log Sanitization:**
   - Custom logging filters scrub sensitive tokens, authorization headers, and credential strings from all stdout/file logs.
3. **Tenant & Workspace Boundaries:**
   - Every dataset, job, lineage graph, and query execution is tagged with `user_id` and `project_id`.
   - Engine services verify resource ownership before querying Parquet or metadata paths.
